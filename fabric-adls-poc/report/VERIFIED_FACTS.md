## Where the current docs differ from the plan in the goal
1. **"Trusted access needs *Enabled from selected networks*, not *Disabled*"**: the docs say both work (FB2). The POC still uses *selected networks*, because your device IP must be allowed for portal or Storage Explorer data access.
2. **"Allow my IP /32"**: /32 isn't accepted, so the bare IP is used (FB15).
3. **"Grant the workspace identity Storage Blob Data Contributor on the container"**: the docs need **storage-account scope**, or **Storage Blob Delegator at account scope plus the data role on the container** (FB3). For least privilege, the POC uses Delegator (account) plus Contributor (container). If the pipeline over TWA refuses that, account scope is the documented fallback (needs a new approval).
4. **"Keep Allow trusted Azure services"**: the docs advise against relying on it for Fabric (FB5). It stays as it is today only if another service (e.g. the Purview scan) depends on it; Fabric uses the resource instance rule.
5. **"VNet gateway connection with workspace identity"**: not supported for gateway connections (FB8). Use an organizational account (created by you in the Fabric UI, FB14) or a service principal.
6. **Pipelines**: the docs support pipelines over **TWA directly** (FB6), with no gateway. The POC tests both and the runbook keeps what passes.
