| 1 | **Offboarding target is not bound to the project (cross-project authorization breach).** `PlanAsync`/`ExecuteAsync` accept any UPN: the person is looked up in the project's people inventory only for the display name, and nothing checks the project's requests, inventory or domain. Any PMO or Operator of any project the agent counts as "connected" (`Tenants.Connected` is also true for every project with no `TenantId`) can plan and confirm offboarding of any account in the agent's tenant: revoke sessions, remove it from every changeable group, delete its Azure role assignments in every subscription in scope (the users-only RBAC condition allows any role, e.g. a subscription Owner assignment of an admin) and disable it. The mitigation PERMISSIONS.md §3 row C promises ("a user holding an Entra directory role is left to people") is not implemented: such a user is still revoked and disabled (test `F5_Verify_finds_leftovers_so_no_completion_mail` line 306 even asserts it). **(probe)** `sample-user-bella` (PMO in SAMPLE-BETA only) planned and confirmed alone the offboarding of a person of SAMPLE-ALPHA: run Completed, account disabled, Alpha group membership removed, Alpha's PMO not told. | Critical | src/core/PmoReview.Core/Offboarding/OffboardingService.cs:43 | In `PlanAsync` refuse (404/409) unless the UPN is an Active, non-retired person of this project's people inventory (or the `DomainId` of a request of this project) and ends with the project's `DomainIdSuffix`; refuse projects whose `TenantId` is empty. In `OffboardingJob.PlanStepsAsync` mark Revoke/Disable/Delete/RBAC steps "left to people" when `getMemberGroups` returns a non-group id (directory role), as PERMISSIONS.md C states. Add tests: other project's person, person not in inventory, directory-role holder. |

| 4 | **Prod guard bypassed by choosing a non-Prod environment for an environment-less mapping row.** A row with no `Environment` applies to every environment (`ReviewChecks.InEnvironment`), the PMO mapping editor allows it in projects that have a Prod environment (`MappingSheetService.cs:144`), and `ProdGuard` takes `scope.Environment ?? r.Environment`, i.e. the environment the requester typed.
