# 04 — UI

> **v2 (17 Oct 2026):** the request flow, roles and checks changed — see `workflows/09-onboarding-flow-v2.md` and `docs/ARCHITECTURE.md`. This SOP records how the phase was built; the build and test commands in `CLAUDE.md` are current.

**Purpose:** SPA on SWA Free for PMO, Reviewer, Maintainer and Operator tasks.

**Inputs:** API contract from Phases 1–3.

**Steps**
1. Vite + React + TypeScript + Fluent UI React v9 in `src/web`.
2. Pages: My Requests; Request form; Review Results (findings, evidence refs, mapping assessment, questions + Copy); Review History (revision, versions, Superseded label); Reviewer Feedback + Failed/Manual queue; Maintainer (SAMPLE rules/mappings).
3. Analyze → Queued/Running → poll 3 s up to 60 s → result; Refresh button; "Last updated".
4. Permanent banner: "This checks request readiness. It does not approve or grant access."
5. Accessibility: labels, focus order, keyboard-only path, empty and error states.
6. Local run: SWA CLI + Functions Core Tools + Cosmos emulator; mock users via SWA CLI auth emulator.

**Outputs:** SPA, local run instructions in `docs/RUNBOOK.md`.

**Validation (exit gate):** local end-to-end with two mock users from different projects; no approve/grant/payment/sign-up controls (grep check).

**Failure handling:** hidden UI is not security — every role gate is also enforced server-side; any UI-only gate is a bug.
