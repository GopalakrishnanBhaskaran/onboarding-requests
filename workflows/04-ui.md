# 04 — UI (v2)

**Purpose:** SPA on SWA Free for requesters, the named Owner, Security, the ID team, the role assignment team, PMO and operators.

**Inputs:** API contract (`docs/ARCHITECTURE.md`).

**Steps**
1. Vite + React + TypeScript + Fluent UI React v9 in `src/web`.
2. Pages: **Requests** (status table: Request ID, requester, stage, waiting on, done, next, time in stage, ADO link); **New / Correct request** (7-step flow and who does what stated upfront; missing fields listed exactly); **Request** (status, progress, decisions, team tasks, final verification, time per stage and wait per team, AI review, notifications, audit trail); **My actions**; **Mapping sheet and response document** (PMO edits; ID team marks a group created); **Issues and reports** (issues list, daily summary, developer report, stuck-review recovery).
3. `components/ApprovalPanel.tsx` is the only place with decision controls, shown only to the person whose decision is due (named Owner, then Security). `components/TeamTaskPanel.tsx`: ID team records TAP **metadata only**; role team records exactly what it assigned.
4. Permanent banner: "The AI agent reviews, routes, verifies and reports. It never approves, creates or assigns …". Sign-out → public `signed-out.html`.
5. While the agent has the next step the request page refreshes every 15 s for up to 5 minutes; Refresh button and "Last updated".
6. Accessibility: labels, focus order, keyboard-only path, empty and error states.

**Outputs:** SPA, local run (`tools/run_local.sh`).

**Validation (exit gate):** `src/web/src/guardrails.test.ts` (no grant/assign/create/payment/sign-up controls, decision wording only in the decision panel, no password or TAP fields, flow stated upfront); Playwright `src/web/e2e/two-projects.spec.ts` (full flow to Completed, Returned, Owner reject, project isolation, mapping sheet, signed-out page).

**Failure handling:** hidden UI is not security — every role gate is enforced server-side; a UI-only gate is a bug.
